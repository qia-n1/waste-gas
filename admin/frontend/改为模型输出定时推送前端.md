# 前端接收后端定时推送（最小改造）

本项目 `admin/frontend` 是纯前端（Vite + Vue），浏览器本身不能直接作为 HTTP POST 服务端。

因此建议同时保留两种集成方案：
1. 前端主动请求（Pull）：前端调用后端 `POST /api/data-fusion/aggregate/run-once`。
2. 后端主动推送（Push）：后端定时任务完成后 `POST FRONTEND_PUSH_URL` 到中转服务，再由 SSE 推给页面。

## 1. 统一数据体（仿照 run-once 返回体）

前端建议统一消费以下结构（与 `POST /api/data-fusion/aggregate/run-once` 返回体保持一致）：

```json
{
  "ok": true,
  "aggregated_at": "2026-04-20 10:52:00",
  "model_result": {
    "ok": true,
    "status_code": 200,
    "body": {}
  },
  "frontend_push": {
    "ok": true,
    "status_code": 200,
    "body": {
      "accepted": true
    }
  }
}
```

失败场景示例：

```json
{
  "ok": false,
  "message": "no rows in current window"
}
```

## 2. 方案 A：前端主动请求（Pull）

适用于：页面需要“点击即触发一次聚合推理”的操作。

### 2.1 前端 API 封装

新建或追加：`src/api/dataFusion.ts`

```ts
import client from "@/api/client";

export interface RunOnceResult {
  ok: boolean;
  aggregated_at?: string;
  model_result?: {
    ok: boolean;
    status_code: number;
    body?: Record<string, unknown>;
  };
  frontend_push?: {
    ok: boolean;
    status_code: number;
    body?: Record<string, unknown>;
  } | null;
  message?: string;
}

export async function runAggregateOnce() {
  const { data } = await client.post<RunOnceResult>("/data-fusion/aggregate/run-once");
  return data;
}
```

### 2.2 页面调用示例

```ts
const result = await runAggregateOnce();
if (result.ok) {
  // 用 result.model_result / result.frontend_push 更新页面
} else {
  // 用 result.message 给出提示
}
```

## 3. 方案 B：后端主动推送（Push）

适用于：无需用户操作，后端定时任务完成后页面自动更新。

### 3.1 推荐接入方式

1. 增加一个轻量中转服务（Node/Express）。
2. 中转服务提供：
   1. `POST /frontend-push`：给后端调用。
   2. `GET /frontend-push/events`：SSE 推给浏览器。
3. 后端推到中转服务的 payload 直接使用 run-once 同款数据体（不要再包一层 event）。
4. 前端页面通过 `EventSource` 订阅 `GET /frontend-push/events`，收到后按同一数据结构处理。

## 4. 中转服务最小示例

新建文件：`admin/frontend/push-relay/server.mjs`

```js
import express from "express";

const app = express();
app.use(express.json({ limit: "1mb" }));

const clients = new Set();

app.post("/frontend-push", (req, res) => {
  // payload 约定为 run-once 返回体
  const payload = req.body || {};
  const data = `data: ${JSON.stringify(payload)}\n\n`;
  for (const client of clients) {
    client.write(data);
  }
  res.json({ ok: true, accepted: true });
});

app.get("/frontend-push/events", (req, res) => {
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");
  res.flushHeaders?.();

  res.write(`data: ${JSON.stringify({ type: "connected" })}\n\n`);
  clients.add(res);

  req.on("close", () => {
    clients.delete(res);
  });
});

app.listen(18002, "127.0.0.1", () => {
  console.log("push relay on http://127.0.0.1:18002");
});
```

安装并启动：

```bash
cd admin/frontend
npm i express
node push-relay/server.mjs
```

## 5. 前端页面接收示例

可在现有 `src/api/sse.ts` 同风格新增一个连接函数：

```ts
export function createTimedPushSse(onMessage: (data: any) => void) {
  const source = new EventSource("http://127.0.0.1:18002/frontend-push/events");
  source.onmessage = (event) => {
    try {
      // data 结构与 run-once 返回体一致
      onMessage(JSON.parse(event.data));
    } catch (e) {
      console.error("timed push parse failed", e);
    }
  };
  source.onerror = () => {
    source.close();
  };
  return () => source.close();
}
```

在页面 `onMounted` 时订阅，`onUnmounted` 时关闭。

## 6. 后端配置

后端启动时设置：

```bash
FRONTEND_PUSH_URL=http://127.0.0.1:18002/frontend-push
```

## 7. 验证

1. Pull：调用 `POST /api/data-fusion/aggregate/run-once`，响应体字段齐全。
2. Push：后端 `/api/data-fusion/status` 中 `last_frontend_push_ok=true`。
3. 中转服务日志看到 `POST /frontend-push`。
4. 页面收到 SSE 后可直接复用 Pull 的同一渲染逻辑。

## 8. 生产建议

1. 中转服务应部署在内网并加鉴权（例如签名 header 或 token）。
2. 建议增加重放保护（request_id + timestamp）。
3. 建议把中转服务放在前端网关层（Nginx/Node BFF）统一管理。
4. 建议前端做去重（按 `aggregated_at`）避免偶发重复渲染。
